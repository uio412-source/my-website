# 상품별 DB 검토

전체 상품은 `data/cards.json.gz`에 저장한다. 각 레코드는 자신의 상품코드로 일치하는 공식 원문을 사용한다. 공시실 또는 상품 페이지에 내용이 없으면 PDF를 찾고, 상품명이 비슷한 카드나 같은 카드사 조건으로 대체하지 않는다.

1. 카드사 공식 목록을 끝 페이지까지 확인한다. 상품코드별 기존 목록과 비교해 신상품, 판매 중단, 변경 상품을 구분한다. 공시 날짜와 설명서 시행일을 각각 기록한다.
2. 상품별 설명서·상품 페이지를 다시 확보한다. 문서 URL, 해시, 읽기 상태, 상품 일치, 확인일, 페이지·섹션 근거를 남긴다. 캐시만 조회하고 확인일을 오늘로 바꾸지 않는다. 해외 브랜드 공통 안내장은 상품 설명서와 구분한다.
3. 기본·추가·특별 적립을 각각 기록한다. 요율, 적립 단위, 포인트 가치, 실제 가맹점·요일·결제 방식, 혜택별 전월실적, 이용건당 조건, 월·연·횟수·공유 한도, 초과분 기본 적립, 가족 합산 여부를 대조한다. 혜택표와 공통 유의사항을 함께 읽는다.
4. 상품권 구매, 선불 충전, 국세, 지방세, 관리비를 분리한다. 실적 인정과 혜택 제공은 서로 다른 항목이다. 연간 기프트·라운지 실적을 기본 적립 실적으로 사용하지 않는다. 제외 목록에 기프트카드라는 단어가 있어도 목록을 버리지 않는다. 적립 계산 안내의 괄호를 전체 제외 목록으로 오인하지 않는다.
5. 해외 결제 수수료 면제는 요율, 국제브랜드, 결제 통화·신용/선불 방식, 실적과 한도를 기록한다. 같은 거래에 적립과 면제가 적용될 때만 합산한다. ATM·현금 인출·환전·정액 외화 수수료는 결제액당 피킹률에 임의 합산하지 않는다.
6. 연회비와 바우처는 제외한다. 최소 전월실적 구간에서 최대 월 금전 혜택을 계산한다. 무실적은 사용 단위당 가치 비율을 계산한다. 대한항공 1마일=20원, ALL 1포인트=33원 가정은 명시한다. 실제 사용금액에 비해 한도가 작으면 통합·영역 한도와 기본 적립을 배분한 완전한 시나리오가 필요하다. 미확인 구성요소가 있으면 최고값은 확인 중으로 둔다.
7. `databaseAudit.reviewStatus=reviewed`는 본문 추출이 아니라 위 조건을 개별 대조한 상태다. `data/product-review-audit.json`의 항목별 누락과 DB 화면의 추가 확인 항목을 해결한다. 본문 존재 여부는 확보 상태이며 모든 조건의 검토 완료를 뜻하지 않는다.
8. 관리자 직접 수정 데이터를 보존한다. 확인된 변경만 반영하고 변경 전후·근거를 남긴다. 필터·상세·최고피킹률·엑셀을 같은 원본에서 갱신하고 회귀 검증 후 기존 접근 권한으로 배포한다.

`refine-policy-database.py`는 확보된 원문의 제외조건 재처리이며 신규 문서 수집을 대신하지 않는다. `review-reward-components.py`는 전체 레코드의 구성요소 누락을 기록하고 개별 대조한 조합만 계산 모델에 연결한다. 검토 스크립트를 실행하기 전에 최신 원문을 수집하고, 최신 변경 상품을 개별 검토한 후 실행한다. 출처를 읽지 못한 상품은 실패 및 미확인으로 남긴다.

통합 DB는 `scripts/build-foundation-database.py`로 전체 상품을 `data/card-foundation.json.gz`에 연결한다. 상품·혜택·조건·계산 모델·결제 판정·공식 문서 각각의 고유번호를 유지한다. 기존 추출 전월실적 후보는 대조한 값과 다른 필드다. HTML 혜택표의 rowspan/colspan을 펼쳐 원래 열 관계를 보존하며, 원문 후보를 확정 수치로 자동 승격하지 않는다. `data/reward-coverage-audit.json`의 미모델링 금전 혜택과 엑셀 `필드별 점검`의 누락을 상품별로 해결한다.

최신 상품 원문 수집·정책 대조 뒤에는 실적 구간의 기본/추가/총 적립 관계를 확인한다. 추가분 단위 한도는 `additionalMonthlyCapUnits`, 특별 총 적립 단위 한도는 `specialRewardCapUnits`, 한도 초과 기본률은 `fallbackRewardUnits`에 기록한다. 다이너스 POINT의 월 5만점은 실적 추가분 한도이고, 100만원 구간 1.8%와 300만원 구간 2.3%는 우리WON페이 포함 총률이다. 새 공시에 요율이 바뀌면 해당 상품의 검토 스크립트도 원문과 함께 수정한다.

검토 후 `audit-reward-coverage.py`, `normalize-reviewed-cap-units.py`, `rebuild-database.mjs`, `refresh-presentation-data.mjs`, `prepare-workbook-data.mjs`, `build-foundation-database.py`를 순서대로 실행한다. 엑셀은 `export-card-workbook.mjs`로 같은 모델에서 만든다. `check-foundation-database.mjs`는 고유키 연결, 대조 전 실적 후보 차단, 실적형 2.3% 산출, 총/추가 한도와 초과 기본 적립을 검증한다. `refresh-foundation-sources.py`의 재확보 성공은 수동 검토 완료가 아니며, 실패한 문서도 엑셀 `원문 재확보`에 포함한다.

매일 오전 6시 Asia/Saigon에 공시실 신상품·변경 점검 작업을 실행한다. 결과 보고에는 신상품·변경·판매중단·확인 실패 공시실 및 미확인 조건을 포함한다.

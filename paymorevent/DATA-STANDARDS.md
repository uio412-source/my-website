# 상품·호텔 표시 규격

- 카드 상세: 혜택 / 바우처 / 전월실적 제외사항 / 혜택 제외사항. 혜택 제목·대상, 비율, 실적, 한도·횟수와 원문을 보존한다.
- 항목별 태그는 `혜택:호텔`, `바우처:호텔`, `전월제외:상품권`, `혜택제외:관리비`처럼 범위를 명시한다. 원문 키워드 분류이므로 예외 조건을 대체하지 않는다. 미수록 자료는 없음으로 단정하지 않는다.
- 피킹률은 최소 실적 구간의 최대 월 적립·할인 ÷ 최소 실적 금액 ×100이다. `calculation=tier-cap`, `maximumVerified=true`와 공식 한도가 확인된 경우만 계산하고 혜자카드는 높은순으로 표시한다. 영역별·통합·횟수 한도를 적용한다. 연회비·바우처는 제외한다. 동일한 해외 결제에 적용되는 검증된 수수료 면제율은 적립률에 더한다. ATM·현금인출·환전·다른 결제 방식의 면제는 합산하지 않는다. 정액 외화 수수료는 결제액과 환율이 없으면 비율로 환산하지 않는다. 월 최대와 연간 반복 가능을 구분한다.
- 사용자 지정 평가값은 대한항공 1마일=20원, ALL 1포인트=33원(0.02유로)이다. rewardRates에 원화 가치·적립 단위·요율·혜택별 최소 실적·월 한도·공식 출처를 보존한다. 무실적 상품은 calculation=unit-rate로 사용금액당 가치 비율을 계산하며 0원을 분모로 쓰지 않는다. 특별적립과 기본적립은 대안이며 중복 합산하지 않는다. 실적형 특별적립이 최소 실적 사용금액에서 한도에 걸리면 완전한 배분 시나리오 없이는 최고값으로 쓰지 않는다. 미확인 최대값은 순위에서 제외한다.
- 상품권 가능/관리비/국세/지방세 상단 필터의 기본값은 paymentEligibility의 **혜택 제공 가능**이다. 전월실적 인정 카드는 사용자가 적용 기준을 `전월실적 인정` 또는 `실적·혜택 모두`로 바꾼 경우에만 해당 기준으로 찾는다. 각 판정에 원문과 조건을 유지하며 일반 소개 키워드와 일부 제외 발췌의 부재는 가능 근거가 아니다.
- 국제브랜드 서비스는 카드 기본 혜택과 분리해 `networkServices`에 저장한다. 브랜드·등급·발급사·정확한 상품 ID가 모두 일치할 때만 연결하며 목록 문구만으로 다른 상품에 상속하지 않는다. 공항 라운지는 국내/전 세계, 무료/할인, 마티나골드 포함 여부, 본인 포함 여부, 동반인 수(0~4), 일·월·연 횟수와 전월실적을 각각 구조화한다. 공항·호텔 발렛과 다이닝도 대상처와 통합한도를 별도로 기록한다.
- 마일리지는 항공 마일 적립, 호텔은 호텔 체인 제휴·특화 서비스, 해외는 실제 해외 혜택, 통신은 통신사·알뜰폰 요금 할인이 주 테마인 상품만 포함한다. 일반 호텔 할인이나 부수적인 통신 할인은 특화 테마에 넣지 않는다.
- 발급 캐시백: 카드사별로 상품명 / 캐시백 환산금액 / 조건(이용·혜택 수혜 이력 포함) / 링크를 표시한다. 공식 액면가가 확인된 현금·상품권·포인트·금액형 쿠폰만 1:1 원화 가치로 합산한다. 선택형 혜택은 choiceGroup별 최댓값 하나만 반영하고 연회비 환급은 제외한다. rewards에 금액·종류·근거·조건·확인 여부를 보존한다. 할인율·항공/호텔 포인트·추첨 경품의 가치는 임의로 더하지 않는다. 최대 금액은 조건 충족 시 표시다.
- 카드사 이벤트: 해외/여행, 포인트/캐시백, 국세 / 지방세, 통신사 등 제휴, 기타의 5개 분류와 카드사·대상 상품(전체/특정)·캐시백·응모형 태그를 사용한다. 공식 전체 목록의 개별 행사에서 행사명·시작일·종료일이 확인되면 verificationLevel=official_list로 게시한다. 세부 조건 미확인은 별도 표시하고 금액·대상 카드를 추정하지 않는다. 기간 미확정만 needs_review로 보류한다. 한국 날짜 기준 종료일이 오늘 이상이고 시작일이 당월 말까지인 행사를 카드사 이벤트 게시판에 포함하며 예정 행사는 예정으로 표시한다. 발급·연회비 행사도 카드사 이벤트 게시판에 포함하되 발급 캐시백 비교의 연회비 제외 규칙은 유지한다. 전체 목록 조회는 끝 페이지까지 읽고 공식 총건수와 대조한다. 목록 수집 실패 시 기존 게시물은 기록된 종료일까지 보존한다.
- 같은 카드의 브랜드·디자인·조건별 파생상품은 familyId로 묶되 원래 상품코드·혜택·약관·자격·상세 링크를 모두 유지한다. 자동 묶음은 같은 발급기관·신용/체크 구분에서 공통 상품명 기준이다.
- 고객 화면에서 데이터·DB 현황을 제거한다. 관리자 진입은 사이트 하단에 둔다. 관리자의 원래 등록·수정·삭제 기능과 접근 제한은 유지한다.
- 호텔은 한국어 표시명(표시용 번역)을 크게, 원문을 작게 병기한다. 원래 호텔 ID/URL/원문명/근거는 유지한다. 등급은 골드와 라운지 접근 상위 등급(메리어트·아코르 플래티넘, 힐튼 다이아몬드, 하얏트 글로벌리스트)을 비교하며 얼리 체크인/레이트 체크아웃/조식/라운지 네 태그만 표시한다. 골드는 노랑, 상위 혜택은 회색이다. 미제공·미보장 태그는 연한 점선으로 구분한다. IHG는 등급과 별도로 40/70박 마일스톤에서 선택하는 Annual Lounge Membership이 필요하다.
- 호텔 목록은 실제 공식 호텔 URL이다. 사이트맵 전체 URL 수록과 운영 호텔 전수·멤버십 참여 전수를 구분한다. URL 유래 표시명은 별도 라벨을 붙인다. 수집 차단·부분 수집은 공식 전체 디렉터리 링크와 함께 공개한다.
- 댓글·커뮤니티는 별도 D1 테이블에 저장하며 카탈로그 갱신/재배포로 지우지 않는다. 로그인 이용자는 작성할 수 있고 본인 또는 관리자만 삭제할 수 있다. 텍스트를 HTML로 실행하지 않으며 이메일·내부 사용자 ID는 공개 응답에 포함하지 않는다. Site 접근 권한은 기존 상태를 유지한다.

## 상품 DB와 조건 근거

- 사이트 하단 `/database`에서 상품 DB를 조회·수정한다. 기존 관리자 권한·동일 출처 검사·D1 수동 덮어쓰기 보존을 사용하며 방문객에게 편집 권한을 부여하지 않는다.
- `documents`에는 실제 관찰한 공식 URL, 상품/설명서/브랜드/개별 서비스 구분, PDF/HTML 구분, 본문 확보 상태, 상품 일치 상태, 확인일, 원문 해시, 혜택·실적 제외·제공 제외 발췌와 적용 범위를 기록한다. `termsUrl`만 있다는 이유로 PDF 확보나 검토 완료로 집계하지 않는다.
- `benefits[].spendExclusions`, `benefits[].benefitExclusions`에 해당 혜택 범위의 제외 조건을 보존한다. `eligibilityRules`는 결제 항목과 적용 혜택을 명시한 규칙이다. `paymentEligibility`는 고객 검색 필터에 사용하는 대표 판정이며, 별도 규칙을 편집할 때 대표 판정을 함께 검토한다.
- 대표 판정은 `spend`와 `benefit` 각각 allowed/excluded/unknown이다. 가능 판정에는 공식 URL과 조건 설명이 필수이며 scope, evidence, basis, channel, limit, checkedAt을 함께 기록할 수 있다. 상품권 구매와 기프트카드/선불카드 충전은 구분한다. 기본 적립·추가 적립·라운지 등 서비스 실적을 서로 확장해서 해석하지 않는다.
- 관리자가 변경한 대표 판정은 저장 시 테마를 재계산하며, 수정 전 themeTags가 새 판정을 덮어쓰지 않는다. summary에는 원문 문서 본문을 넣지 않는다. 고객 카탈로그 API는 no-store로 최신 저장 내용을 제공한다.
- `databaseAudit.reviewStatus=reviewed`는 수동으로 범위와 예외를 검토한 상태다. 본문 추출만으로 검토 완료로 표시하지 않는다. 자료 미확인은 혜택이 없다는 뜻이 아니다.
- `scripts/enrich-card-documents.py`는 기존 공식 문서 및 상품 페이지에서 실제 관찰한 링크만 수집한다. `scripts/apply-document-database.py`는 원문과 기존 근거를 구조화하고 전월실적 제외 목록이 적립 제외 목록으로 이어 붙은 경우 경계를 분리한다. PDF는 Poppler로 한글을 추출한다. 수집 캐시는 체크아웃의 임시 파일이며 원문 발췌와 수집 상태는 `data/document-research.json`에 보존한다.
- 재수집은 원문 추출과 별도 수동 검토를 거쳐야 한다. 수집 실패 시 과거의 확보·검토 기록을 삭제하지 않으며 확인일을 최신으로 꾸미지 않는다. `scripts/check-database-accuracy.mjs`, `scripts/check-catalog-management.mjs`로 데이터 형식·상품권/충전 구분·검색 판정 변경·권한·저장 보존을 검증한다.

- DB 엑셀은 배포 시점의 원본 스냅샷이다. 전체 상품·혜택 고유번호를 연결하고, 피킹률 계산, 실적·한도 구간, 기본/추가/특별 적립 모델, 결제 항목 판정, 제외사항, 공식 원문 표, 설명서, 재확보 결과 및 필드별 점검을 담는다. 웹 관리자 수정은 다음 내보내기 전까지 엑셀에 반영되지 않는다.
- 실적 후보와 대조한 실적을 분리한다. 미확인을 0원·무제한·가능으로 변환하지 않는다. 모든 상품은 마스터에 유지하며 원문과 모델이 없는 상품도 누락하지 않는다. 부족한 항목은 혜택 고유번호로 관리한다.
- 전월실적형 요율은 해당 구간 사용금액에 적용한 실제 혜택으로 산출한다. 총 월 한도, 추가분 한도, 특별적립 전체 포인트 한도, 초과 기본 적립을 구별한다. 포인트/마일 단위 한도는 환산 가치 변경 시 원화 한도도 변한다. 기본률만 입력된 상품에 추가 금전 혜택이 누락되면 최고피킹률을 확정하지 않는다.

- 제외목록 안의 기프트카드·바우처 구매 제외는 목록을 버리는 사유가 아니다. 적립 계산 문장 안의 괄호(적립제외 대상 금액 제외)를 제외목록 제목으로 인식하지 않는다. 줄바꿈된 목록과 전월 실적 표기를 연결하며, 자동 판정은 원문을 다시 대조할 때 이전 가능 값을 초기화한다.

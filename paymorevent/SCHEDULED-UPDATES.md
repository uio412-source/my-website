# 매일 카드 DB 구축·공시·이벤트 갱신

전 카드사 DB 정규화·미완료 상품 재개·신상품/상품공시 갱신은 기존 카드 검토 자동화가 `CARD-DATABASE-WORKFLOW.md`를 수행합니다. 카드 검토는 하루 검증·저장 성공 50건의 카드사별 묶음 처리로 운영하며 `batch_source`(최대 10건)와 `batch_import`(최대 50건)를 사용합니다. 기존 연결 이벤트 자동화는 아래 이벤트·발급 캐시백 갱신을 수행합니다. 두 기존 스케줄을 유지하고 새 스케줄을 만들지 않습니다.

이 사이트는 소유자에게만 공개되어 있다. 현재 접근 권한을 유지한다. 이 문서는 카드사 이벤트와 발급 캐시백의 일일 갱신용이며 개인정보나 인증정보를 포함하지 않는다.

1. 연결된 Sites 프로젝트의 `get_site`로 소유자 전용 상태와 지원되는 서비스 접근 토큰을 읽는다. 토큰은 이 사이트 요청의 `OAI-Sites-Authorization: Bearer …` 헤더로만 보내고 출력하거나 저장하지 않는다.
2. 삼성카드, KB국민카드, 신한카드, 우리카드, 하나카드, 현대카드, 롯데카드, NH농협카드, BC카드 순서로 POST /api/sync/events에 JSON {"issuer":"카드사명"}을 한 회사씩 호출한다. 회사별 상태를 누적한다. 202이면 실행 중이므로 `GET /api/sync/events`로 확인한다. 완료 결과를 읽어 카드사별 실제 검증 수와 오류를 구분한다.
3. `GET /api/sync/events`의 `sync.discovered`에서 신규·변경된 상세 링크를 확인한다. `GET /api/catalog`에서 현재 카드상품 ID와 이벤트 ID를 읽는다.
4. 삼성·국민·신한·우리·하나·현대·롯데·농협·BC의 공식 이벤트 상세와 페이북 전체 공개 이벤트를 확인한다. `data/personal-benefit-sources.json`의 우리 꾹, 신한 마이샵, 현대 3층 선물, KB Pay 할인팩, BC 마이태그, 하나 Pick, 삼성 LINK 공개 페이지와 공개된 관련 이벤트 상세를 매일 함께 확인한다. 공개 진입 페이지 확인과 실제 혜택 상세 확인을 구분한다. 개인별 로그인 혜택을 모든 회원에게 적용되는 공통 행사로 등록하지 않는다. 네이버페이·카드고릴라·실제 발급 채널의 최신 발급 캐시백도 확인한다. 동적 응답이 막힌 출처는 지원되는 검색·브라우저로 확인한다. 오래된 검색 제목만으로 금액이나 기간을 확정하지 않는다.
5. 공식 상세에서 확인한 새 이벤트는 `POST /api/sync/events/import`에 JSON 배열로 보낸다. 각 기록은 id, kind(card/cashback), issuer, chain(null), title, description, benefitText, tags, category(해외/여행, 포인트/캐시백, 국세 / 지방세, 통신사 등 제휴, 기타), channel, cashbackAmount(원 또는 null), cashbackIsMaximum, startsAt, endsAt, bookingEndsAt(null), stayEndsAt(null), requirements, participation, sourceUrl, imageUrl(null), status(active/upcoming/expired/needs_review), verifiedAt(한국 날짜), verificationNote, cardIds, cardNames를 가진다. 기간은 YYYY-MM-DD 또는 null이다. 금액·시작일·대상 상품을 확인하지 못하면 추정하지 않는다. cardIds는 정확한 대상과 현재 DB ID가 일치할 때만 넣는다. 신용/체크, 국제브랜드, 신규고객, 응모, 이용실적, 지급일, 제외항목과 중복/환수 조건을 함께 기록한다.
6. 기존 ID 또는 동일 공식 이벤트의 안정적인 ID를 재사용한다. 광고성 최대 금액과 기본 캐시백을 구분해 혜택요약에 적는다. 이미 저장된 이벤트를 중복 생성하지 않는다. 공식 전체 목록의 개별 행사에서 행사명·시작일·종료일이 확인되면 verificationLevel=official_list로 게시한다. 세부 조건 미확인은 별도 표시하고 금액·대상 카드를 추정하지 않는다. 기간 미확정만 needs_review로 보류한다. 한국 날짜 기준 종료일이 오늘 이상이고 시작일이 당월 말까지인 행사를 카드사 이벤트 게시판에 포함하며 예정 행사는 예정으로 표시한다. 발급·연회비 행사도 카드사 이벤트 게시판에 포함하되 발급 캐시백 비교의 연회비 제외 규칙은 유지한다. 전체 목록 조회는 끝 페이지까지 읽고 공식 총건수와 대조한다. 목록 수집 실패 시 기존 게시물은 기록된 종료일까지 보존한다. 공식 목록은 개별 이벤트로 보지 않는다. 관리자 수동 수정과 삭제는 DB의 별도 덮어쓰기 레이어에 보존된다.
7. `/api/catalog`을 다시 읽어 저장·대상 카드 연결·종료일을 검증한다. 데이터만 갱신하며 소스를 재배포하지 않는다. 상태가 같으면 알리지 않고, 수집 실패가 지속되거나 사용자 조치가 필요할 때만 알린다.
8. 카드 DB 검토에서는 국제브랜드 `brand`·`service` 원문과 발급사 상품설명서를 함께 읽고 브랜드·등급·발급사 선택서비스·정확한 상품 ID를 대조한다. 공항 라운지는 국내/전 세계, 무료/할인, 마티나골드, 본인, 동반인 0~4명, 일·월·연 한도, 실적과 통합 한도를 `networkServices`에 분리 기록한다. 인천공항 발렛, 국내호텔 발렛, 국제브랜드 다이닝·커피도 대상처·횟수·예약·주차비 조건을 기록한다. 동적 페이지나 목록 제목만 확인한 경우 다른 카드로 상속하지 않고 미확인으로 남긴다.

발급 캐시백은 현금·상품권·포인트·금액형 쿠폰 중 확인된 1:1 원화 가치만 rewards로 저장한다. 선택형 혜택은 중복 합산하지 않는다. 신규발급 연회비 환급 행사는 제외한다. 카드사 이벤트 category는 해외/여행, 포인트/캐시백, 국세 / 지방세, 통신사 등 제휴, 기타를 사용하며 응모 여부는 entryRequired로 별도 저장한다. 카드사 이벤트는 당월 미종료와 예정 행사를 표시하고, 발급 캐시백 비교는 진행 중 행사만 표시한다. 대상 상품·브랜드·신용/체크·발급기관이 확인되지 않으면 cardTarget을 넓게 지정하지 않는다.

카드 분류는 자료에 근거한 paymentEligibility(실적 인정/적립·할인 각각 allowed/excluded/unknown)를 사용한다. 일부 발췌에 제외 키워드가 없다는 이유로 가능 처리하지 않는다. 피킹률은 최소 실적 구간의 최대 월 적립·할인 ÷ 최소 실적 ×100이며 영역·통합·횟수 한도를 적용한다. 연회비·바우처·연간 보너스는 계산에 넣지 않는다. 사용 단위와 명시된 마일/포인트 평가 가정을 표시하고 동일 거래의 검증된 수수료 면제만 합산한다. 실적용 추가 소비와 지속 사용의 실적 인정 조건은 별도 설명한다. 전체 최대 한도 미확인은 혜자카드 순위에서 제외한다.

오전 6시(Asia/Seoul) 기존 연결 스케줄을 유지한다. 이 문서는 연결된 Site 소스의 최신 커밋에서 읽는다. 다른 스케줄을 중복 생성하지 않는다.


## 카드·이벤트 연결 점검 (2026-10-17)

- 카드 전용은 안정적인 cardIds 또는 명시한 familyIds, 공통 행사는 cardTarget의 발급사·신용/체크·브랜드·제외조건으로 연결한다. 이름에 키워드가 있다는 이유로 대상 범위를 넓히지 않는다. 카드 ID 일치도 브랜드·제외조건을 우회하지 않는다.
- 트래블러스는 기본·스페셜·캐릭터형의 family-kb-09563을 사용한다. 토심이 등 표시명 차이는 정확한 상품 ID·공식 대상과 대조한다. Mastercard 행사에는 국내전용·다른 브랜드를 연결하지 않는다.
- 신규 발급 행사에는 기존 고객 제외, 발급 채널, 발급·이용 마감일을 별도로 저장한다. 응모와 MTR 등록·혜택 활성화는 구분하며 분기별 재활성화를 표시한다. 외화 혜택을 확인되지 않은 원화 금액으로 환산하지 않는다.
- KB 모바일 evntId/evntSerno와 PC eventNum은 동일 행사 키로 통합한다. 목록 갱신이 검증된 대상 연결을 지우지 않게 mergeEventRefresh를 사용한다. 상세 재확인일과 목록 확인일을 분리한다.
- data/event-link-updates.json의 검토된 KB 상세는 공식 본문 지문과 기간이 일치할 때만 상세 검증을 유지한다. 본문·기간이 변경되면 조건 재확인으로 전환한다.
- 돈키호테 통합 미션, KB 페이백 및 MTR 개별 행사는 같은 혜택을 중복 합산하지 않는다. 공식 내용과 공통 제외조건이 충돌하는 온라인 예약 행사는 추천 보류로 표시한다.
- 갱신 후 /api/catalog에서 카드군별 진행 이벤트 수·needs_review·브랜드 제외를 확인하고, /cards/kb-09563 및 /?card=kb-09563#events 연결을 점검한다.

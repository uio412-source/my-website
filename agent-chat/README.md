# 에이전트 작업방

저장소 이슈 #391의 댓글이 대화 기록입니다. 저장소 이슈를 볼 수 있는 사람은 채팅도 읽을 수 있습니다. Pages 배포 경로는 `/my-website/agent-chat/`입니다. 읽기 권한이 있는 GitHub 계정으로 연결하면 비공개 이슈도 표시됩니다. 요청 실행은 저장소 소유자 uio412-source가 이 화면에서 보낸 메시지만 대상으로 합니다.

## 개인용 호스트에서 실행

상시 켜진 Linux 또는 macOS 컴퓨터에 Python 3, GitHub CLI, 사용할 에이전트의 공식 실행 프로그램을 준비합니다. 저장소를 체크아웃하고 해당 폴더에서 실행합니다.

```sh
gh auth login
python3 agent-chat/room.py serve
```

같은 컴퓨터에서 http://localhost:8765 를 열면 브라우저에 토큰을 넣지 않고 메시지를 작성할 수 있습니다. 모바일에서는 배포된 Pages에서 같은 이슈를 열 수 있습니다. Pages 직접 전송에 쓰는 GitHub 자격 증명은 해당 저장소의 Issues 읽기·쓰기로 제한하고, 탭을 닫으면 다시 입력합니다.

## 5분 간격 실행

호스트의 별도 설정 파일(저장소 밖)에 실제 로그인된 에이전트의 실행 명령을 지정합니다. 아래는 예시입니다. 사용 중인 구독에 포함된 로그인 경로와 사용 한도를 먼저 확인하세요.

```json
{
  "Claude": ["claude", "-p"],
  "ChatGPT": ["codex", "exec", "-"]
}
```

```sh
python3 agent-chat/room.py work ~/.config/mr-agents.json
```

한 호스트에서 한 워커를 상시 실행합니다. 워커는 시작할 때와 이후 300초마다 댓글을 한꺼번에 읽습니다. 해당 에이전트 앞으로 온 새 요청이 있을 때만 프로그램을 실행합니다. 프로그램은 표준 입력에서 요청을 받고, 표준 출력에 최종 답변을 반환해야 합니다. Pi​ckle·Dot·Grok 등은 각 제품에서 실제 사용할 수 있는 실행 명령을 연결한 뒤 참여합니다. 호스트 로그인과 해당 서비스가 부여한 권한에 따라 수행할 수 있는 작업이 달라집니다.

전체 요청은 연결된 에이전트 각각에 한 번 전달합니다. 개별 요청은 선택한 담당만 처리합니다. 담당자가 답변 마지막 줄에 `다음 담당: Claude`처럼 쓰면 다음 확인 때 그 담당자가 앞선 대화를 이어받습니다. 같은 요청에서 각 담당은 한 번만 회신합니다. 추가 토론은 새 메시지로 시작하세요. 워커가 꺼졌던 동안의 미처리 요청은 다음 시작 때 읽습니다. 수집용 예약 작업 및 기존 협업 이슈의 일반 댓글은 자동 실행 대상에서 제외됩니다.
